# AUR Automatic Release

This document explains how to automatically synchronize MMLang to [AUR](https://aur.archlinux.org/packages/mmlang) using GitHub Actions. The workflow is only responsible for updating `PKGBUILD` / `.SRCINFO` and pushing them to AUR; it does not build binary packages in CI.

## Artifacts

- `PKGBUILD` (`/PKGBUILD:1`): `pkgname=mmlang`, `source` pulls `https://github.com/aura-deak/MMLang/archive/refs/tags/v$pkgver.tar.gz`, `depends=('python' 'python-bitarray')` (`PKGBUILD:9`), and `package()` installs `common.py/asm_core.py/vm_core.py` etc. into `/usr/share/mmlang` and creates `/usr/bin/mmlang-asm|run|debug`.
- `.SRCINFO` (`/.SRCINFO:1`): AUR metadata, parsed and generated by the workflow from `PKGBUILD` (no `makepkg` required), and updated in sync with `PKGBUILD`.
- Workflow `.github/workflows/aur-publish.yml`: Triggered only on `release: published` (GitHub Release) and `workflow_dispatch`. It performs only version/hash updates and AUR pushes (the `push` tag no longer triggers it directly).

## First Release (Create the AUR Package)

If `aur@aur.archlinux.org:mmlang.git` is empty, the workflow will automatically `git init` and `push HEAD:master` during the `Push to AUR` step. You can also initialize it manually:

```bash
git clone ssh://aur@aur.archlinux.org/mmlang.git /tmp/aur-mmlang
cp PKGBUILD .SRCINFO /tmp/aur-mmlang/
cd /tmp/aur-mmlang
git add PKGBUILD .SRCINFO
git commit -m "Initial import 1.0.0.1"
git push origin master
```

First, register an account on AUR and add your public key under **My Account → SSH Public Key**.

## Configure GitHub Secrets

In `aura-deak/MMLang`, go to **Settings → Secrets and variables → Actions** and add:

| Secret | Description |
|---|---|
| `AUR_SSH_PRIVATE_KEY` | The full AUR private key (`-----BEGIN OPENSSH PRIVATE KEY-----`). The corresponding public key must already be added to AUR. It is recommended to `ssh-keygen -t ed25519 -C "aur@mmlang"` and not set a passphrase. |

AUR SSH always uses the `aur` user (`ssh://aur@aur.archlinux.org/mmlang.git`).

> If this Secret is not configured, the workflow runs in **dry-run** mode: it only updates the local `PKGBUILD`/`.SRCINFO` and prints the results, without pushing to AUR.

## Release Process

### Automatic (Recommended)

```bash
git commit -am "feat: ..."
git push origin main
git tag v1.0.0.2 -m "Release v1.0.0.2"
git push origin v1.0.0.2
# 然后在 GitHub 创建 Release（选择同名 tag v1.0.0.2 → Publish release）才会触发 AUR 同步
# 单独推送 tag 不会触发（工作流已改为 on: release）

# 工作流在 Release 发布后将：
# - 下载 https://github.com/aura-deak/MMLang/archive/refs/tags/v1.0.0.2.tar.gz
# - 计算 sha256 并更新 PKGBUILD 的 sha256sums
# - 从 PKGBUILD 生成 .SRCINFO（纯 bash，无需 Arch 容器/makepkg）
# - 推送到 AUR master
```

### Manual Trigger

In GitHub, go to **Actions → Publish to AUR → Run workflow**. You can enter a `tag` (e.g., `v1.0.0.2`). If left blank, the latest tag from `git describe` will be used.

### Update Only `pkgrel`

When fixing packaging scripts for the same version, manually modify the `pkgrel` in `PKGBUILD:4`. The workflow will automatically reset it to `1` for new versions. For patches within the same version, you must increment it manually and retrigger the workflow.

## Local Verification (Optional)

```bash
# 检查 PKGBUILD 语法与哈希
curl -L -o /tmp/source.tar.gz https://github.com/aura-deak/MMLang/archive/refs/tags/v1.0.0.1.tar.gz
sha256sum /tmp/source.tar.gz

# 如已安装 pacman/makepkg，可本地生成 .SRCINFO 校验（非必需，工作流已用 bash 生成）
makepkg --printsrcinfo > /tmp/check.srcinfo && diff -u .SRCINFO /tmp/check.srcinfo
```

Installation on the user side (after release):

```bash
yay -S mmlang
# 或 paru -S mmlang
# 或 git clone https://aur.archlinux.org/mmlang.git && cd mmlang && makepkg -si
```

## Workflow Details

- Runtime environment: `ubuntu-latest` (no `archlinux` container, no `base-devel/makepkg/namcap`; only performs uploads and updates).
- Triggers: `on.release.types: [published]` (only on Release; the `push` tag does not trigger it) + manual tag input via `workflow_dispatch`.
- Version detection (`aur-publish.yml:22`): `inputs.tag` > `release.tag_name` > `refs/tags/*` (manual compatibility) > `git describe`.
- Update logic: `sed` modifies `pkgver/pkgrel`; `curl` downloads the tarball and computes `sha256sum`; `sed` modifies `sha256sums`; then Bash parses `pkgdesc/url/license` from `PKGBUILD` to generate `.SRCINFO`.
- SSH: `~/.ssh/aur` private key + `ssh-keyscan aur.archlinux.org`, `Host aur.archlinux.org User aur`.
- Push: The `master` branch of `ssh://aur@aur.archlinux.org/mmlang.git`.
- Write-back: If `PKGBUILD/.SRCINFO` has changes and is not a detached HEAD, it attempts `git push origin HEAD` (requires `contents: write`).

## Frequently Asked Questions

**Q: I see `AUR_SSH_PRIVATE_KEY not set`?**  
A: You are in dry-run mode. Re-run the workflow after configuring the private key.

**Q: `Permission denied`?**  
A: Check that the private key contains the full `BEGIN/END` text, that the public key has been applied to AUR, and that the key is `ed25519`.

**Q: I pushed a tag, but AUR has not been updated.**  
A: This workflow is now triggered only by `release`. Pushing a tag alone will not execute it. You must create a Release on GitHub (`Releases → Draft a new release → 选择 tag → Publish release`) or manually enter a tag using `workflow_dispatch`. If it still does not update, check the `Push to AUR` logs for `No changes to push`.
